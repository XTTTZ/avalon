# 规则、状态与安全设计

## 权威状态机

主流程为 `lobby → reveal → team → teamVote → questVote → team / lady / assassination / finished`；身份发放后的任意未结算阶段都可由刺客直接转入 `finished`。

全部规则只在 `server/engine.ts` 执行，浏览器提交意图。UI 不能指定身份、阵营、当前阶段、投票结果或获胜者。任务结束由最后一张合法任务票的事务自动推进，不依赖房主在线。每次开局都会重新随机排列座位，并独立随机分配角色，从第一张玩家卡开始按序轮换。确认身份须全员完成；组队严格过半才通过，平票拒绝。

前端只用玩家卡表达带队顺序，房主进入排序状态后拖动卡片，保存时通过 `reorder` 提交全部玩家 ID 的排列并设置 `mode=rotation`。手机使用 Pointer Events、pointer capture 与仅排序时的 `touch-action:none`，CSS order 保持捕获元素不被移走；触点靠近边缘自动滚动，取消拖动/切后台恢复该次拖动前的草稿。方向键提供替代操作。整个编辑过程不写数据库，保存才执行一次带版本与幂等保护的命令。

每次 `start` 都对玩家列表和角色牌堆分别执行 Fisher–Yates 洗牌，每次抽取独立调用服务端 `node:crypto.randomInt`，不使用时间戳种子、`Math.random` 或共享排列。允许抽中原顺序或上局同一身份，不通过强制排除这些结果引入偏差。`orderCustomized` 仅标记当前手动排列，开局清零，绝不跳过任何一次洗牌；请求重放使用事务回执，不重复洗牌或发身份。

本局后续轮次不再随机；房主开局后仍可按现实座位改序。改序会清除旧的下一任指定，保留当前队长、玩家 ID、身份、已投票和私人笔记；下一次轮换从当前队长的新位置往后取一位。若旧房间正等待手动指定队长，保存排序后从第一位开始恢复按序带队。旧 `assignLeader` / `manual` / `shuffleSeats` 服务端协议暂保留兼容旧客户端，新界面不再提供这些入口。

房主踢人由 `kick` 统一处理。大厅和结算阶段可直接移除；局中必须显式传 `endGame=true`，在同一事务内结束整局、清空未完成票据并移除成员，不会出现只结束没踢掉或踢掉后继续投票的中间态。结算用 `departedPlayers` 的公开字段保留被移除玩家及角色记录，不保留账号标识；被移除用户无法再获取该房间或私人笔记。结算期间，其余玩家各自的私人昵称和笔记仍保留该玩家，继续按笔记所有者隔离；重新开局清除离开玩家的结算快照和对应笔记目标，人数不足时不能开始。

结算阶段允许每位玩家自行 `leave`，离开快照继续保留在其余玩家的公开结算中，本人的成员资格和笔记访问同时撤销。房主可在任意阶段执行 `dissolve`：服务端写入立即过期的墓碑、清空成员并删除全员笔记；墓碑在定时清理前保留明确的“房间已被房主解散”响应，也保证房主重试同一请求不会重复执行。

默认角色采用常见中文参考配置，而非把新增坏人全部设为普通爪牙：5 人为梅林、派西维尔、忠臣、莫甘娜、刺客；6 人增加一名忠臣；7 人增加一名忠臣和奥伯伦；8 人为三名忠臣及莫甘娜、刺客、爪牙；9 人为四名忠臣及莫甘娜、刺客、莫德雷德；10 人在 9 人配置上加入奥伯伦。官方规则固定阵营比例，但允许玩家自行替换可选特殊角色，因此界面仍允许在自定义模式调整。

身份发放后，刺客可在结算前的任意阶段刺杀一名其他玩家；命中梅林则邪恶胜，刺错则好人胜，刺杀立即结束本局。提前刺杀权限只存在于刺客本人的秘密投影，前端入口只在身份页实际显示身份时出现；点击后身份立即隐藏，独立目标窗口继续保留，避免受五秒显示时间限制。圆桌和其他玩家的投影不出现入口。好人完成三次任务且刺客尚未行动时进入最终刺杀阶段；三次任务失败则邪恶胜，连续五次组队拒绝则邪恶胜。7 人以上第四轮须两张失败票。善良只能提交成功，邪恶可选成功/失败。参考原版出版规则扫描：[The Resistance: Avalon](https://avalon.fun/pdfs/rules.pdf)。

自定义支持 5–12 人，邪恶至少一人且少于一半；特殊角色至多一张，忠臣/爪牙可重复。梅林和刺客成对启用，派西维尔需要梅林。总轮数 3–9；获胜任务数 `w` 为 2 到 `floor((总轮数+1)/2)`，确保在最多 `2w−1` 轮内决出任务胜负，后面的配置轮次可能不使用。每轮人数 1 到总人数；失败门槛不超过本轮人数和邪恶人数；拒绝上限 1–10。11–12 人默认 4 恶，其余善，任务人数 3/4/5/6/6，属于本应用扩展。

## 数据与并发

生产环境使用 Neon PostgreSQL 和 `NeonStore`。`avalon_commit` 在一个 SQL 事务中按键排序加 advisory lock、核对全部读取的 UUID revision、统一提交写入；缺失键同样加锁，删除重建产生新 revision，防止 ABA。冲突最多重跑 8 次，之后返回可重试的 CONFLICT；失败回调只核验读取，不写入。表与函数撤销 PUBLIC 权限，只授权不继承 `neon_superuser` 的 SQL 角色 `avalon_runtime` 执行有限函数；owner 连接串只用于 migration，运行连接串只存在于 Worker Secret。

`shared/types.ts` 是白名单响应契约；`shared/rules.ts` 只有公开规则。`server/engine.ts` 的 RoomState 含服务端秘密，绝不直接返回。`projectRoom` 按可信 userId 生成公共状态和本人视图。前端没有数据库驱动，也不能直接连接 Neon。

API 的 `userId` 从服务端签名会话提取，玩家公开 playerId 为独立随机 ID。所有非登录操作检查身份与房间成员资格。房主只有配置、开局、终止等权限，不继承他人秘密与笔记权限。结算才返回全桌角色；任务票的玩家映射在每次任务结束立即删除。

存储事务通过单次数据库函数提交，房间状态、去重回执和必要用户记录原子更新；不跨多个 Neon HTTP 请求假装持有事务。本地 FileStore 用串行队列和原子文件替换实现同样语义（只用于单进程开发）。普通命令必须匹配版本和 phaseKey；ready/组队票/任务票可在同一阶段并发提交，不允许把旧阶段的票投到新阶段。请求 ID 去重，重复请求重新生成当前权限投影，不返回旧身份快照。票投出后不可修改。任务票原文不写客户端持久存储、应用日志或公开历史。

新房间号在 `1000–9999` 中使用密码学随机数生成，以房间号为数据库文档主键。同一事务读取该主键、确认不存在、创建房间并保存用户回执；并发碰撞由事务重试处理。占用时换号，最多尝试 32 次后返回可重试错误，绝不使用覆盖写入作为兜底。已过期但尚未清理的文档仍占用号码；清理删除后才可复用。接口继续接受已有六位房间号，不迁移或重编号进行中的对局。

笔记文档按 `roomInstanceId + ownerUserId` 隔离，调用方不能指定 owner；保存要求 revision，避免多窗口静默覆盖。响应严格限制字段和文本长度，拒绝危险对象键与未知命令。房间状态有上限，写操作按用户限频；Worker 暖实例内的限流不是全局防护，公网滥用还需 Cloudflare 账户级规则和资源开关。

公开名字在服务端统一 NFKC、空白与大小写比较，创建/加入/改名时在房间事务内检查唯一性。私人昵称只参与当前观看者的渲染，不进入公开玩家或日志。新操作事件记录公开玩家 ID 和当时公开名，前端按 ID 解析当前昵称；旧纯文本事件只按完整已知句式匹配，歧义时保留原文，避免误替换规则文字。

房间闲置期限按最后一次有效游戏操作计算：大厅 24 小时、游戏中 48 小时，结束后固定 24 小时；读请求、重放幂等操作和笔记保存不续房。空大厅立即失效。私人笔记绑定不可复用的房间 `instanceId`；每小时清理时事务核对活跃房间，延长仍有效笔记的期限，避免再开一局后误删。旧数据保留兼容路径，新建同号房间不能读取旧实例笔记。客户端以房间创建时间和本人玩家 ID 区分新的成员关系，清空旧笔记/草稿/修订号并忽略迟到响应，同一房间再来一局则保留笔记。

## 登录与恢复

### 数据库流量优化

Worker 暖实例复用一个按数据库连接隔离的 `NeonStore`。仅缓存已完成的 rooms/users JSON 快照，最多 64 条、合计约 8 MiB；单条超过 4 MiB 时跳过。每次读取调用 `avalon_get_cached`，由数据库核对 UUID revision：相同仅返回修订号，变化返回新快照，删除返回空值。缓存没有跳过鉴权的 TTL 窗口，所有响应仍经 `projectRoom`；私人笔记不进入跨请求缓存。

事务使用实际查询确认过的 revision 执行原子 CAS。缓存值通过 JSON 解析及拷贝隔离，失败事务不会修改其他请求的快照；并发请求只复用各自发起查询时捕获的版本。到期判断仍使用 API 当前时间，删除重建换 UUID。新增 migration 保留旧 `avalon_get`，支持应用回滚。

这减少的是 Neon 到 Worker 的重复数据传输，并不免除数据库查询，也不保证固定的节省比例。冷启动、跨实例或房间每次变化时仍需取完整状态；实际收益应按 Neon 出站和 Worker 使用量观察。

### 手机与 PWA

浅色/深色/跟随系统偏好仅保存为 `avalon.theme`，首屏脚本在 React 加载前应用主题，系统模式响应系统外观变化。设置入口对所有玩家一致；二维码始终保留浅色背景，身份卡保持原有固定尺寸与自动隐藏逻辑。

PWA 使用 Avalon 独立图标、manifest、安装提示和手机安全区域适配。生产 Service Worker 只拦截入口导航：在线直接走网络，断网显示静态重连页；API、WebSocket、身份、私人笔记和投票均不写 Cache Storage。没有 `skipWaiting`、强制刷新或安装后自动重载，避免打断进行中的游戏。离线页恢复网络后重新载入，由原会话恢复玩家。

### 会话与网络

生产使用 guest 身份。浏览器生成 256 位 deviceSecret，服务端使用稳定的 `IDENTITY_SECRET` 派生身份；会话由独立的 `SESSION_SECRET` 签名。会话有效 180 天，每次应用打开验证并刷新，服务器记录最近房间。本地只持久保存会话、deviceSecret 和房间位置，不缓存角色、任务选择或房间秘密。

显式「刷新」读取完整的本人房间投影及本人笔记，保留页面/草稿，重复点击合并，失败可重试，不重复提交命令。活动页面先通过短时 ticket 连接房间 Durable Object；WebSocket 只通知 `{roomInstanceId, gameId, version}`，收到后再用 HTTP 拉取本人投影。订阅建立后立即复核版本以补首次读取和握手之间的窗口；重复、乱序和漏通知都由版本比较处理。后台停止连接和轮询，恢复前台/在线立即读状态。WS 失败使用有上限的退避和低频 polling，正常连接也保留稀疏 HTTP 核对。网络丢失导致结果不确定时，用户可重试同一 requestId；服务器始终防止重复投票与跨阶段重放。

实时连接将 ticket 请求与 WebSocket 握手分别限时 30 秒；只有收到有效房间版本通知才视为订阅完成。每 20 秒检查心跳，未响应时重连；网络切换提示触发更短的存活检查。`navigator.onLine` 只影响提示，不能阻止实际请求，避免 VPN 导致恢复永久停止。前台事件共用连接，读取期间的新通知合并为一次后续读取；旧连接、旧房间和旧读取代次的迟到结果均被忽略。网络变化和手动刷新只取消读请求，绝不取消后自动重放秘密投票。

每个页面随机生成 `connectionId`，经已签名 ticket 绑定用户；服务端替换同页遗留连接，同一玩家超出 3 个连接时退休最早的页面。被替换页面保留 HTTP 兜底，但不自动争抢 WebSocket，重新进入前台或手动刷新时可重新订阅。心跳由 DO 的自动应答处理，支持休眠，不需要每个 ping 都唤醒应用代码（[Cloudflare WebSocket 文档](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)）。

## Worker 与实时边界

Cloudflare Worker 同时提供 Static Assets、HTTP API、`/api/health` 健康检查和 Durable Object 路由。静态资源不经过动态逻辑；`/api/*` 与 `/ws` 优先进入 Worker，避免 SPA fallback 把错误接口返回为 HTML。DO 使用 WebSocket Hibernation API，连接附件只保存最少身份，空闲时没有定时循环。Neon commit 成功后才广播版本；广播失败不得把已成功命令改成失败，也不得触发新 requestId 重放。

权威状态只在 Neon。DO 可以缓存版本和短时 ticket，不保存另一份 RoomState。所有写入口、alarm 和兼容 HTTP 路径继续执行数据库 CAS；房号路由必须同时验证不可复用 instanceId，防止四位房号复用串房。一个玩家和一个房间的连接数有上限，被踢、离开、解散、过期或授权到期后关闭连接。

## 部署后仍须验收

自动化覆盖本地同源 API、纯状态机、Neon adapter、Worker runtime、WebSocket 恢复和浏览器流程。真实 Neon 事务、DO 休眠唤醒、Cloudflare 自定义域名和不同移动网络仍须在目标环境验证。生产验收还需记录 Worker/DO 请求与 CPU、Neon compute、存储和出站，确认朋友局规模落在免费额度预算内。
